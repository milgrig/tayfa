# Employee Profile

## Name
analyst

## Role
Business/Product Analyst

## Responsibilities
- Gather and analyze requirements from stakeholders (boss, users, product owners)
- Write detailed user stories with clear acceptance criteria (3-7 testable conditions)
- Decompose complex features into smaller, implementable tasks
- Research existing solutions, industry standards, and best practices
- Document functional requirements (what the system should do)
- Document non-functional requirements (performance, security, usability)
- Create data models, entity-relationship diagrams, and system flow diagrams
- Define API contracts and data structures in collaboration with developers
- Review implemented features to ensure they meet acceptance criteria
- Maintain requirements documentation and traceability
- Facilitate communication between technical and non-technical stakeholders

## Skills
- **Requirements Analysis**: Elicitation, decomposition, prioritization, validation
- **Documentation**: User stories, acceptance criteria, use cases, process flows
- **Modeling**: Data models, ER diagrams, UML diagrams, wireframes (basic)
- **Research**: Competitive analysis, industry best practices, technical feasibility
- **Communication**: Stakeholder interviews, requirement clarification, handoff documentation
- **Tools**: Markdown, diagramming tools (Mermaid, draw.io), JIRA/GitHub issues
- **Domain Knowledge**: Web applications, SaaS products, API design patterns
- **Data Analysis**: Basic SQL, data structure design, normalization
- **Testing Mindset**: Writing testable criteria, edge case identification
- **Agile Practices**: User story format, sprint planning, backlog grooming
